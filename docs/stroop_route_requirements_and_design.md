# Stroop Route（ストループ・ルート / 意色交差パズル）Webアプリ要件定義書・詳細設計書 (v1.0.0)

本ドキュメントは、脳科学における「ストループ効果（Stroop Effect）」をゲームメカニクスに昇華させた一筆書きパズルゲーム『Stroop Route（意色交差パズル）』の、本番水準WebアプリケーションおよびPWA（Progressive Web App）としての開発・実装・運用に関する包括的な要件定義書および詳細設計書である。

初版（v0.0）、実装仕様改訂版（v0.1）を経て、本番デプロイ（Vercel稼働）、PWA完全対応（Service Workerオフラインキャッシュ、マルチサイズアプリアイコン）、コンテナクエリ（`100cqw`）による全ステージ均一グリッド設計、下部HUDの最適化、モーダルUIの完全分離（レイアウトシフト解消）を反映した**正式リリース版（v1.0.0）**である。

## 1. プロジェクト概要・コンセプト

### 1.1 背景と目的

人間の脳は、文字を見ると無意識にその意味を読み取ってしまう特性（**読字の自動化**）を持つ。文字の意味とフォントのインク色が食い違っている場合（例：青色インクで書かれた「あか」）、色の判定に強い干渉・遅延が生じる。これを**ストループ効果**と呼ぶ。
本作は、このストループ干渉を「一筆書き迷路の接続ルール」として統合し、前頭前野の**抑制制御（Inhibitory Control）**、**認知的柔軟性（Cognitive Flexibility）**、空間ワーキングメモリ（Working Memory）を同時に鍛える新感覚の脳トレ・パズルゲームである。

### 1.2 コアバリュー

1. **ストループ干渉 × 一筆書き**: 文字の意味とインク色の制約を解き明かしながら、一筆書きでゴールを目指す快感。
2. **反転ゲート（⚡）によるルール逆転**: ゲート通過時に「文字➔色」から「色➔文字」へと判定基準が一瞬で反転し、脳のギアチェンジを強制。
3. **日本語3表記（漢字・カタカナ・ひらがな）の混合**: 表意文字（漢字）と表音文字（カナ）が混在することで言語野と視覚野の干渉を極限まで強化。
4. **4×4ファインダー × スワイプ展開迷宮**: スマホ縦画面に最適な4×4マスのファインダー表示を維持しながら、スワイプ操作で最大10×10（9区画）の大迷宮をストレスなく探検。
5. **コンテナクエリ（`100cqw`）による均一グリッド**: ステージサイズ（4×4〜10×10）に関わらず、画面内に見える4×4枠の1マスサイズ・文字サイズ・フォントバランスを完全均一化。
6. **ミニドットHUDによる現在地把握**: 画面を圧迫せず、全ステージで高さ固定（44px）のHUDにより盤面が上下に動かない安定した画面遷移を実現。
7. **デイリーチャレンジ ＆ SNS共有**: 毎日日替わりで共通生成されるパズルと、解いた軌跡をワンタップでSNSにコピー・共有できるバイラル性（本番URL: `https://stroop-route.vercel.app` 連携）。
8. **完全PWA対応**: ホーム画面追加（iOS/Android）、高解像度ネオンアイコン、オフラインキャッシュによる圏外・機内プレイ対応。

## 3. ゲームルール・パズルメカニクス詳細仕様

### 3.1 カラー定義とストループ属性

ゲーム内で使用する基本色は以下の5色とする。それぞれの色について「意味（Word）」と「インク（Ink）」が独立した属性として各マスに保持される。

| 色ID | 意味名称 (name) | ひらがな (kana) | カタカナ (kata) | 漢字 (kanji) | インクHex (hex) | 枠線Hex (borderHex) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `RED` | あか | あか | アカ | 赤 | `#f87171` | `#ef4444` |
| `BLUE` | あお | あお | アオ | 青 | `#60a5fa` | `#3b82f6` |
| `GREEN` | みどり | みどり | ミドリ | 緑 | `#34d399` | `#10b981` |
| `YELLOW` | きいろ | きいろ | キイロ | 黄 | `#fbbf24` | `#f59e0b` |
| `PURPLE` | むらさき | むらさき | ムラサキ | 紫 | `#c084fc` | `#a855f7` |

### 3.2 パズルクリアの終了条件

* **クリア条件**: **「スタートマスから出発し、自己交差せずにストループ規則を満たしながらゴールマスへ到達すること（Pathfinding / 経路探索）」**。
* **非Hamiltonian Path**: 盤面上の全マスを踏破する必要はない。スタートからゴールへの有効な経路が1本でも成立した瞬間にクリアとなる。
* 盤面上に配置された未使用のマスは「妨害セル（Distractor）」として機能し、プレイヤーのミスリードを誘発する。

### 3.3 移動制約と判定タイミング

プレイヤーは現在パスの先端（Tip）から隣接するマスを選択して経路を伸ばす。

1. **直交隣接移動**: 上下左右の4方向（Manhattan距離 = 1）にのみ移動可能。斜め移動は不可。
2. **自己交差禁止（一筆書き）**: すでに現在のパスに含まれているマスへの再進入は禁止（Undoによる取り消しを除く）。
3. **スタートマスからの1手目判定**:
   * スタートマスに配置された初期属性（通常モードから開始）に基づき、**スタートマスの `word` と、1手目マスの `ink` を比較判定**する。
4. **通常モード（Normal Mode / isReversedMode = false）**:
   * 直前マスの「文字の意味（Word）」と、移動先マスの「インク色（Ink）」が一致しなければならない。
   $$\text{Target.ink} = \text{Prev.word}$$
5. **反転ゲート（⚡ GATE）マス進入・脱出時の判定タイミング**:
   * **進入時**: 直前のマスからGATEマスへの進入判定は、**進入前のモード（直前のルール）**に従って行う。
   * **進入完了時**: GATEマスに進入した瞬間、モードフラグが即時反転する（`isReversedMode = !isReversedMode`）。
   * **脱出時**: GATEマスから次のマスへ進む際の判定は、**反転後の新ルール**に基づいて行う（GATEマスの属性を起点として判定）。
6. **ゴールマス（GOAL）への進入判定**:
   * ゴールマス自体も通常のストループ整合性判定の対象となる。直前のセルとの整合性（通常時：直前Word＝ゴールInk、反転時：直前Ink＝ゴールWord）を満たしていなければゴールに進入できない。
7. **アイコン・テキスト色**:
   * 盤面上の START（旗）、GOAL（星）、GATE（⚡雷）の文字およびアイコンは、視認性を高めるため白色（`text-white`）で統一。

### 3.4 日本語3表記混合仕様（Japanese Notation Progression）

* **Stage 1（入門）**: ひらがな（あか、あお、みどり...）のみ。基本ルール学習に集中。
* **Stage 2（初級）**: ひらがな ＋ カタカナ（アカ、アオ...）がマス目ごとに交互出現。
* **Stage 3以降・自動生成**: ひらがな・カタカナ・漢字（赤、青、緑...）が完全ランダム混合。表意文字（漢字）が混ざることで、読字抑制の難易度が大幅に向上。

### 3.5 Undo（1手戻す）・リセット・手詰まり仕様

1. **Undo（1手戻す）**:
   * **トリガー**: UI上の「1手戻す」ボタン押下、直前のパスセル（先端の1つ手前）のタップ/クリック、キーボードの `Z` キー / `BackSpace` キー。
   * **挙動**: パス先端のセルを除外（`path.pop()`）。通過したGATE数に基づいて `isReversedMode` を再評価。
2. **リセット**:
   * **トリガー**: UI上の「リセット」ボタン押下、またはキーボードの `R` キー。
   * **挙動**: パスをスタートマスのみに初期化。
3. **手詰まり（Dead End）検出と案内**:
   * **検知条件**: パス先端（Tip）から進める有効マスが **0個** になった瞬間。
   * **演出・UI案内**: 先端セルを振動（shakeアニメーション）させ、低音のエラー音を再生。トーストでリカバリーを誘導。

### 3.6 ルート候補アシスト

* 現在のパス先端から進入可能なマスにエメラルドグリーンのパルスリングを表示。
* Stage 1〜2 はデフォルトON、Stage 3以降はデフォルトOFF（設定画面でいつでも切替可能）。

## 4. 画面拡張・コンテナクエリ＆スライディングカメラ

### 4.1 コンテナクエリ（`100cqw`）による全ステージ均一グリッド（★v1.0.0）

Stage 1（4×4）、Stage 3（5×5）、Stage 4（7×7）、Stage 5（10×10）の全ステージにおいて、画面内に見える基準窓（4×4ファインダー）の1マスサイズ、フォントサイズ、余白比率を完全に同一にするため、CSS Container Query Units を導入している。

```css
#gridWrapper {
  container-type: inline-size;
  --gap: 8px;
  --pad: 8px;
  --cell-size: calc((100cqw - 16px - 24px) / 4);
}
```

* **均一性**: ステージを切り替えても、盤面の枠の大きさ、セルの大きさ、文字のサイズが1ピクセルも変動しない。
* **スクロール迷宮**:
  - 4×4マス（Stage 1, 2）: 全体表示（スクロールなし）
  - 5×5マス（Stage 3）: 画面幅に合わせた固定表示
  - 7×7マス（Stage 4）: 4×4ファインダー ＋ 3マススライディング（2×2区画）
  - 10×10マス（Stage 5）: 4×4ファインダー ＋ 3マススライディング（3×3区画）

### 4.2 単一フレーム外枠（Labyrinth Frame）

* 迷宮全体（7×7、10×10）を紫色のネオングロー枠線（`border: 4px solid rgba(168, 85, 247, 0.8)`）で囲み、スライディング時にも迷宮の外壁であることを直感的に把握可能。

### 4.3 3マススライド・1マスオーバーラップ

* カメラオフセット `(camR, camC)` は3マス刻みで移動。
* 移動後も直前マスの1列/1行がファインダー内に残り、迷子を防止。

### 4.4 操作系（タッチ・マウス・キーボード）の統合

* **タッチ（スマホ）**:
  - 先端マスから開始 ➔ パスのドラッグ描画。
  - 先端以外から開始 ➔ 迷宮のフリックスワイプ（3マススライド）。
* **PCマウス**: クリック前進、ドラッグ連続接続、直前セルクリックでUndo。
* **PCキーボード**: 矢印キー / WASD（移動）、Z / BackSpace（Undo）、R（リセット）。

## 5. UI/UX・HUD・モーダル仕様

### 5.1 下部ミニドットHUD（`MiniDotHud.tsx`）

盤面下部に配置される常時表示HUDパネル。

* **縦幅の固定（`h-11` / 44px）**: 全ステージでHUDの高さを完全固定し、ステージ切替時に盤面が上下に動く現象を解消。
* **横幅の統一**: 盤面の紫ネオン枠と左右の幅（`px-4`）を完全一致。
* **3×3 / 2×2 ミニドット**: 現在見ている区画をシアンネオングローで点灯。ドットタップで該当区画へ直接ジャンプ。Stage 5のドット重なりを解消した整然配置。
* **凡例**: START（緑）、GATE（⚡白）、GOAL（黄）をコンパクトに表示。

### 5.2 上部情報カード（モードバナー）

* **通常モード**: シアンネオン、「文」バッジ、「通常モード: 【文字の意味 ➔ インク色】」
* **反転モード**: パープルネオン点滅、「色」バッジ、「⚡ ルール反転中: 【インク色 ➔ 文字の意味】」
* **TARGETインジケーター**: 「次は赤色インク」など次に進むべきターゲット色を常時表示。

### 5.3 遊び方・ルールのヒント（`HowToModal.tsx` ★v1.0.0）

* **モーダル化によるレイアウトシフト防止**: 従来のインライン展開から、すりガラスオーバーレイモーダルに変更。
* **ゼロピクセル安定性**: ヒント開閉時に盤面のサイズや座標が1ピクセルも動かず、快適にルール確認が可能。
* **大外ラッパー `w-full` 適用**: スマホ画面幅いっぱいに盤面がフィットし、無駄な左右余白を排除。

### 5.4 クリア画面とSNS共有（`ClearModal.tsx` ★v1.0.0）

* クリアタイム・手数・脳科学スコア獲得（抑制制御、認知的柔軟性、空間ワーキングメモリ）を表示。
* **「共有」ボタン**: ラベルを短くシンプル化し、`whitespace-nowrap` によりスマホ狭幅でも2行折り返しを防止。

## 6. PWA（Progressive Web App）仕様 (★v1.0.0)

* **iOS全画面対応**:
  - `apple-mobile-web-app-capable: yes`, `apple-mobile-web-app-status-bar-style: black-translucent`
